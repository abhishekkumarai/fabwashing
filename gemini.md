## Hosting Architecture

```
Vercel (Frontend)  ←→  Render (Backend API)  ←→  Render Managed Postgres
```

### Frontend → Vercel

- **Account:** `3abhishekkumar@gmail.com`
- Import repo on Vercel, set **Root Directory = `frontend`**.
- Set env var **`NEXT_PUBLIC_API_URL`** = your Render API URL (e.g. `https://laundrypro-api.onrender.com`).
- **Must be set before the build** — it is inlined into the client bundle at build time and cannot be changed at runtime.
- Deploy.

### Backend + DB → Render

Configured via [`backend/render.yaml`](./backend/render.yaml) (Render Blueprint):

| Setting        | Value                                                                                      |
|----------------|--------------------------------------------------------------------------------------------|
| Service type   | Web service                                                                                |
| Runtime        | Python                                                                                     |
| Plan           | Free                                                                                       |
| Root dir       | `backend`                                                                                  |
| Build command  | `pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate && python manage.py seed` |
| Start command  | `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 3`                       |
| Database       | Managed Postgres `laundrypro-db`, free plan                                                |

**Render auto-provisions:**
- `DATABASE_URL` — wired from the managed Postgres instance.
- `DJANGO_SECRET_KEY` — auto-generated.

**You must manually set after deploy:**
- `CORS_ALLOWED_ORIGINS` — set to your Vercel URL (e.g. `https://your-app.vercel.app`). Marked `sync: false` in the blueprint, so Render won't prefill it.

### Local Dev → Docker Compose

```bash
docker compose up --build
```

| Service        | Port | Image                         |
|----------------|------|-------------------------------|
| `db` (Postgres)| 5432 | postgres:16-alpine            |
| `api` (Django) | 8000 | python:3.12-slim              |
| `web` (Next.js)| 3000 | node:20-alpine (multi-stage)  |

- Frontend: http://localhost:3000 (redirects to `/login` → click **Sign in**)
- API:      http://localhost:8000/api/
- Migrations and seed data run automatically on container start.

### Local Dev — No Docker (SQLite fallback)

**Backend:**
```bash
cd backend
pip install -r requirements.txt
python manage.py migrate
python manage.py seed
python manage.py runserver 127.0.0.1:8000
```

**Frontend:**
```bash
cd frontend
npm install --legacy-peer-deps
# .env.local already sets NEXT_PUBLIC_API_URL=http://localhost:8000
npm run dev
```

## Environment Variables

See [`.env.example`](./.env.example) for the full list.

| Variable                | Where set        | Purpose                                                              |
|-------------------------|------------------|----------------------------------------------------------------------|
| `DATABASE_URL`          | Backend          | Postgres connection string. Unset → falls back to SQLite.            |
| `DJANGO_SECRET_KEY`     | Backend          | Django secret key. Auto-generated by Render in prod.                 |
| `DEBUG`                 | Backend          | `1` for local/Docker, `0` for prod (Render sets this).               |
| `DJANGO_ALLOWED_HOSTS`  | Backend          | Includes `localhost`, `127.0.0.1`, `.onrender.com`.                  |
| `CORS_ALLOWED_ORIGINS`  | Backend          | Set to Vercel URL after frontend is deployed.                        |
| `NEXT_PUBLIC_API_URL`   | Frontend (build) | Django API base URL. **Must be set before `next build` runs.**       |

## Deploy Checklist

1. Push repo to GitHub.
2. **Render:** New → Blueprint → point at repo → provisions API web service + managed Postgres automatically.
3. **Vercel:** Add Project → set Root Directory to `frontend` → set `NEXT_PUBLIC_API_URL` to the Render service URL → deploy.
4. **After both are live:** go to the Render service → Environment → set `CORS_ALLOWED_ORIGINS` to your Vercel app URL.
